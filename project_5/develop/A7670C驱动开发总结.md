# A7670C 短信驱动开发总结

## 项目背景

STM32 + FreeRTOS 项目，集成 A7670C 4G 模块实现短信发送。  
驱动文件：`driver_a7670c.c / .h`，依赖 `stdlib_usart` 串口层。

---

## 踩坑记录

### 1. 模块型号误判
购买链接标注"支持2G 3G 4G"，实际为两种模块混售：SIM900A（仅2G）和 A7670C（4G Cat-1）。SIM900A 在当地 2G 已关闭，完全无法注册网络。  
**结论：使用 A7670C，网络注册命令用 `AT+CEREG?`，不能用 `AT+CREG?`。**

### 2. SIM 卡类型问题
- 物联网卡（IMSI 46007x 开头）：无短信权限，`+CEREG: 0,6`
- 纯 4G 流量卡：同样无短信权限  

**结论：必须使用支持语音+短信的普通手机卡（移动/联通）。**

### 3. 硬件电平不兼容
A7670C TX 为 1.8V TTL，STM32 RX 高电平识别阈值约 2.0V，直连导致接收乱码。板载 RS232 转换芯片（MAX232）输出 ±3.3V，与模块完全不兼容。  
**结论：绕过 RS232 芯片，直接从 STM32 GPIO 引出 TTL 信号；STM32 RX 引脚加 10kΩ 上拉到 3.3V。**

### 4. 模块启动时序问题
`Init()` 调用过早，模块尚未启动完成就发送 AT 命令，自检全部失败。  
**结论：Init 中监听 `SMS DONE` URC，等待模块就绪后再执行自检。**

### 5. 指令回显干扰解析
模块默认 ATE1（回显开启），每条 AT 命令被原样回显一遍。`WAIT_LINE` 拿到的第一行是回显的命令本身而非数据。  
**结论：Init 中发送 `ATE0` 关闭回显。**

### 6. 多行响应被覆盖
`AT+CIMI` 响应为连续两行（IMSI + OK），间隔 <1ms。单缓冲方案中数据行被 OK 覆盖，`WAIT_LINE` 只读到 OK。  
**结论：引入 4 槽环形队列 `rxLineQueue`，所有响应行入队后逐行出队匹配，不丢失任何行。**

### 7. RAM 不足（L6406E 链接错误）
队列（4×64=256B）+ diag 结构体（~540B）超出芯片剩余 RAM。  
**结论：`RX_QUEUE_SIZE=4`，`A7670C_RX_LINE_MAX_LEN=64`，`A7670C_PDU_HEX_MAX_LEN` 保持 320 不可缩小。**

### 8. 网络注册未完成就发送（unknown error）
`SendSms` 在网络注册完成前执行，返回 `+CMS ERROR: unknown error`。  
**结论：`SendSms` 开头加 `WaitNetworkReady()`，轮询 `AT+CEREG?` 确认 stat=1/5 后再发。**

### 9. PDU 构建失败（pduLen==0）
RAM 压缩时 `A7670C_PDU_HEX_MAX_LEN` 被误改小，`needed > pduHexSize` 判断失败返回 0。  
**结论：恢复 `A7670C_PDU_HEX_MAX_LEN = 320`。**

## 最终驱动架构

### Init 流程
```
DRIVER_A7670C_Init()
  ├── 注册 UART 字节回调
  ├── 等待 "SMS DONE" URC（最长 10s）
  ├── ATE0 关闭回显
  └── RunDiag() 4 步自检
        ├── STEP1: AT → OK
        ├── STEP2: AT+CIMI → IMSI
        ├── STEP3: AT+CSQ  → rssi
        └── STEP4: AT+CEREG? → stat（最长等 30s）
```

### SendSms 流程
```
DRIVER_A7670C_SendSms(phone, content)
  ├── WaitNetworkReady()   轮询 AT+CEREG?，最长 30s
  ├── UTF-8 → UCS2 大端字节序列
  ├── BuildPduHex()        构建 PDU 十六进制串
  ├── AT+CMGF=0            切换 PDU 模式
  ├── AT+CMGS=<len>        等待 ">"
  ├── 发送 PDU + Ctrl+Z（0x1A）
  └── 等待 "+CMGS:" 确认发送成功
```

### 接收行队列（关键设计）
```
UART 中断字节回调
  └── 拼行完成 → push 进 rxLineQueue（4 槽环形队列）

WaitResp()
  └── 循环 dequeue 逐行匹配，不丢失任何响应行
```

## 自检诊断速查

调试时在 Watch 窗口展开 `a7670cInfo.diag`：

| 字段 | 含义 | 异常值说明 |
|------|------|-----------|
| `allPass` | 四步全部通过 | 0 = 存在问题 |
| `step1Result` | AT 握手 | FAIL → 串口未通，检查接线/波特率 |
| `step2Result` | SIM 卡识别 | FAIL → 检查卡座/卡类型 |
| `imsi` | IMSI 字符串 | 空 → SIM 卡未读到 |
| `csqRssi` | 信号强度 | 99 = 天线未接；<10 = 信号极弱 |
| `ceregStat` | 4G 注册状态 | 6 = 物联网卡；2 = 搜网中；1/5 = 正常 |
| `stepXRaw` | 各步原始回复 | 直接查看模块返回的字符串 |

## 关键宏配置

```c
#define A7670C_RX_LINE_MAX_LEN   64U    /* 响应行缓冲，节省 RAM */
#define RX_QUEUE_SIZE             4U    /* 接收队列深度，节省 RAM */
#define A7670C_PDU_HEX_MAX_LEN  320U   /* PDU 缓冲，不可缩小 */
#define A7670C_UCS2_MAX_CHARS    70U   /* 单条短信最大字符数 */
#define A7670C_TIMEOUT_MS      5000U   /* 普通 AT 命令超时 */
#define A7670C_CEREG_TIMEOUT_MS 30000U /* 网络注册超时 */
#define A7670C_BOOT_TIMEOUT_MS 10000U  /* 模块启动等待超时 */
```

## 硬件连接

| 信号 | A7670C 侧 | STM32 侧 | 备注 |
|------|----------|---------|------|
| TX→RX | TX（1.8V TTL） | PA10 | PA10 加 10kΩ 上拉到 3.3V |
| RX←TX | RX（1.8V TTL） | PA9 | 3.3V TTL 直连，模块可兼容 |
| GND | GND | GND | 必须共地 |

> **重要：绕过板载 RS232 转换芯片（MAX232），直接使用 STM32 GPIO TTL 信号。**

## 公有数据结构（供其他模块读取）

```c
typedef struct {
  a7670cState_e state;          /* IDLE / BUSY */
  uint8_t       lastSmsResult;  /* A7670C_SMS_OK / A7670C_SMS_FAIL */
  uint8_t       rxLine[64];     /* 最近一条模块回复（调试用） */
  uint8_t       rxLineReady;    /* 新行就绪标志 */
  a7670cDiag_t  diag;           /* 自检诊断信息（见上表） */
} a7670cInfo_t;

extern a7670cInfo_t a7670cInfo; /* 全局可访问 */
```

## API

```c
/* 初始化驱动，阻塞约 10~55s（启动+自检） */
void DRIVER_A7670C_Init(void);

/* 发送短信，阻塞约 0~35s（等网络+发送） */
/* 返回 A7670C_SMS_OK(1) 或 A7670C_SMS_FAIL(0) */
uint8_t DRIVER_A7670C_SendSms(const char *phone, const char *content);
```
