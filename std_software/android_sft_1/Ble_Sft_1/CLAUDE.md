
## 项目概述

Android BLE 上位机工程，配套下位机：**ESP32-C3 + ESP-IDF 5.5.3 + NimBLE**。

实现功能：BLE 扫描、连接、GATT 服务发现、特征订阅(Notify/Indicate)、特征读写、RSSI 实时刷新、BLE 终端日志。

## 任务

esp32下位机端会操作服务1的特征1，来实现app与esp32之间的双向数据传输。数据格式如下：
固定16 字节帧结构：
| 字节位置     | 值         | 说明                                                         |
| ------------ | ---------- | ------------------------------------------------------------ |
| `[0]`        | `0x55`     | 包头 1                                                       |
| `[1]`        | `0xAA`     | 包头 2                                                       |
| `[2]`        | `0x01`     | 控制字段                                                     |
| `[3] ~ [12]` | 数据内容    | UTF-8 编码，最多 **10 字节**，不足补 `0x00`                  |
| `[13]`       | CRC8       | 固定为 `0x00`                                                |
| `[14]`       | CNT        | 包计数，`0x00~0xFF` 循环递增                                 |
| `[15]`       | `0xFF`     | 包尾                                                         |
控制字段说明：
0x17~0x20：ESP32向APP发送数据包
0x21~0x24：APP向ESP32发送数据包

esp32通过订阅的方式向APP广播数据包，使用控制字段0x17~0x20，通过数据格式也可以看到，每帧数据最多包含2个4字节变量，2个1字节变量
APP通过写的方式向esp32发送数据包，使用控制字段0x21~0x24，每帧数据最多包含2个4字节变量，2个1字节变量

现在需要实现这个协议解析，并且写宏配置，用来配置这个协议适用于哪些服务下的特征，比如默认值为服务1，特征1。留出最终解析数据的接口：CMD，4byteVar_1，4byteVar_2，1byteVar_1，1byteVar_2
