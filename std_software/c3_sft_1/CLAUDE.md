- 项目背景：
    这是一个基于 ESP-IDF 5.5.3 + NimBLE 的 BLE 外设工程，实际硬件目标为 ESP32-C3。  
    工程主体来自 Espressif 的 `bleprph` 示例，并在当前仓库中保留了适合继续开发的 BLE 外设框架。
    它的核心功能是与STMT32进行串口通讯，把STM32发来的数据通过BLE转发到Android上位机APP
    它向外提供三个GATT Service服务，其中第一个是官方例程给出的服务，另外两个是我的自定义服务。每个服务下都会提供两个特征：写 ，通知。
    写特征用于上位机APP向ESP32发送数据，通知特征用于ESP32向APP发送数据，实现数据的双向通信。
    先根据我当前给出的任务，一步一步完善这个工程。

- 任务：
    driver_stm32模块用于接收和发送来自stm32的串口数据包，波特率112500，默认使用esp32的usart1，esp32的RX是20引脚，TX是21引脚
    driver_ble模块只需要封装一个串口自定义协议即可，协议格式如下，固定16 字节帧结构：
    | 字节位置     | 值         | 说明                                                         |
    | ------------ | ---------- | ------------------------------------------------------------ |
    | `[0]`        | `0x55`     | 包头 1                                                       |
    | `[1]`        | `0xAA`     | 包头 2                                                       |
    | `[2]`        | `0x01`     | 控制字段                                                     |
    | `[3] ~ [12]` | 数据内容    | UTF-8 编码，最多 **10 字节**，不足补 `0x00`                  |
    | `[13]`       | CRC8       | 固定为 `0x00`                                                |
    | `[14]`       | CNT        | 包计数，`0x00~0xFF` 循环递增                                 |
    | `[15]`       | `0xFF`     | 包尾                                                         |
    控制字段说明：
    0x09~0x12：STM32向ESP32发送数据包
    0x13~0x16: EPS32向STM32发送数据包
    0x17~0x20：ESP32向APP发送数据包
    0x21~0x24：APP向ESP32发送数据包
    与STM32和APP的双向通讯默认不进行CRC校验，CRC字段为0x00时默认通过校验
    分别留出与STM32端、APP端最终解析数据与装填数据的接口：CMD，4byteVar_1，4byteVar_2，1byteVar_1，1byteVar_2

    


- 约束
对于driver层的模块，都要新建一个且仅一个以该模块名称命名（模块名+Info_t，如：ws2812Info_t ws2812Info）的公有结构体，并在h中extern，用于管理该模块的相关数据。对于一个模块中有多个通道控制的情况，使用结构体数组管理该模块

- 验收标准：
    0 error， 0 warning
