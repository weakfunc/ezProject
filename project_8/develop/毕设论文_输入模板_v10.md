## ⚠️ 全局硬约束（Claude 严格遵守）

1. **所有输入图片必须出现在最终论文中**：你提供的每一张图片（除 G1 任务书图片），Claude 必须插入论文相应章节并展开描述。一张都不许丢。
2. **代码只选重要函数讲解**：贴的应用层代码 Claude 不必逐函数解释，只挑选**相对重要的核心函数**单独开小节讲解，简单的辅助函数一笔带过或不提。
3. **目录由 Claude 动态决定**：模板 G2 目录仅作参考，Claude 可根据项目复杂度增减小节、调整名称。
4. **字数 18000~22000 字**：技术内容（第三、四、五章）占 70% 左右；第二章详细，第一、六、七章精简。
5. **摘要 ≤ 300 字**（中文摘要）。
6. **大章节标题后不插过渡段**：例如"第四章 软件设计"和"4.1 下位机软件设计"之间不要写描述性段落，直接进入 4.1 内容。同样 4.1 和 4.1.1 之间也不插过渡段。
7. **段落开头不要总结性套话**：禁止"总的来说""综上所述""一般而言"这类开场白，直接进入正文。
8. **硬件/软件章节差异化描述**：简单模块（如 LED、按键、蜂鸣器）简单描述；复杂模块（如传感器、通信、电机驱动）详细描述。不要平均用力。
9. **第六章测试章节精简**：≤5000 字，少分小节，结合项目背景描述测试内容并解释结果即可，**不要堆砌测试意义的论述**。
10. **测试数据用表格不用散文**：探测距离、误差、分辨率等指标必须**至少 30 次测量**，给出均值和方差，输出 Markdown 表格。Claude 可自行编写满足设计指标的合理数据。**响应时间指标不测**。
11. **机械结构章节简述**：使用 SOLIDWORKS 建模 + 拓竹 A1 打印机 3D 打印 + PLA 耗材，简单交代即可，不展开。
12. **语气词节制**：每 1000 字大约 10 处语气词或第一人称用词即可，不必刻意堆砌"啊""吧"。
13. **禁用词汇**：论文中不得出现"分层架构""框架""分层式""分层结构""模块化框架"等暗示已有代码模板的概念。也不要主动说明软件是怎么"分层"的，只需自然描述各个文件/模块各自的职责。

## 2. 软件文件职责（论文中需用通用术语描述，不要强调"分层"）

| 内部叫法 | 论文中表述 | 职责 |
|---|---|---|
| task 层（userApp） | 应用文件 / 主任务文件 | 业务逻辑，开发者主要工作区 |
| func 层（userFunc） | 功能模块文件 | 跨驱动的逻辑整合，如通信处理 |
| driver 层（userDriver） | 驱动文件 | 各外设的驱动封装 |
| stdlib 层（userLib） | 基础工具函数 | 通用工具（延时、CRC、字符串等） |
| HAL 层（Core/） | 硬件抽象层接口 | ST 官方 HAL 库 |

调用规则：上层可调用下层（论文中不强调这个规则）。

## 3. FreeRTOS 任务规划

项目固定使用两个 FreeRTOS 任务：

| 任务名 | 周期 | 职责 |
|---|---|---|
| task_system | 10ms | 系统级周期任务，维护基础工具状态机和通信更新 |
| task_user1 | 2ms | 应用级任务，承担主要业务逻辑 |

task_user1 内部通过 `taskCnt` 计数器取余实现多周期：

```c
if (taskCnt % 5 == 0)   { /* 10ms 周期逻辑 */ }
if (taskCnt % 50 == 0)  { /* 100ms 周期逻辑 */ }
if (taskCnt % 250 == 0) { /* 500ms 周期逻辑 */ }
if (taskCnt % 500 == 0) { /* 1s 周期逻辑 */ }
```

**论文中描述**：可写为"主任务以 2ms 为基础调度周期，通过计数器取余实现 10ms / 100ms / 500ms / 1s 等多级时间片"。

## 4. 命名规范（论文中提到代码命名时遵守）

- 任务函数：`xxxTaskInit()` / `xxxTaskUpdata()`（注意是 Updata 不是 Update，这是项目代码实际拼写）
- 任务结构体：`xxxTaskInfo_t` + `extern xxxTaskInfo_t xxxTaskInfo`
- 驱动函数：`DRIVER_XXX_Init()` / `DRIVER_XXX_Update()` / `DRIVER_XXX_DoSomething()`
- 驱动结构体：`xxxInfo` 或 `xxxInfo[CH_COUNT]`
- 命名风格：小驼峰（变量/函数）+ 大驼峰_t（结构体）+ 全大写_下划线（宏）
- 注释语言：中文
- 内存分配：全静态分配，禁用 malloc

## 5. 通信链路（若项目有 BLE/APP 通信）

通信链路结构：

```
STM32 ←USART1→ ESP32 ←BLE→ 手机 APP
```

- STM32 通过 USART1 与 ESP32 通信，统一使用 16 字节定长帧
- ESP32 作为 BLE 协处理器，将 STM32 数据透传给 APP，反之亦然
- 应用层通过 `remoteVar_TX[16]` / `remoteVar_RX[16]` 两个变量池读写，不需要操作底层帧

`remoteVar_t` 是 4 字节联合体：

```c
typedef union {
    uint8_t  raw[4];
    uint32_t var_uint32;
    int32_t  var_int32;
    float    var_float;
} remoteVar_t;
```

槽位有效宽度：

- TX/RX 索引 [0][1][4][5][8][9][12][13] → 4 字节槽位（float / uint32 / int32）
- TX/RX 索引 [2][3][6][7][10][11][14][15] → 1 字节槽位

**关键约束**：TX[0]~[3] 不会到达 APP（被 ESP32 截留），发送给 APP 的数据使用 TX[4]~[15]。

**论文中描述**：可写为"主控通过串口与无线通信模块交换数据，无线通信模块再通过低功耗蓝牙将数据透传至手机端。为简化业务层代码，作者设计了变量池机制，应用层只需读写约定的变量数组即可完成双向通信"。

## 6. 字节序处理（论文若涉及通信细节）

APP 端以大端序发送 4 字节字段，STM32 端 USART 接收处理函数已自动翻转为小端序。**应用层直接读写 remoteVar 即可，无需关心字节序**。

## 7. 上位机（若项目有 APP）

- 平台：Android 原生
- UI 框架：Jetpack Compose + Material Design 3
- 通信：BLE GATT
- 主页面：单页 HomeScreen，包含项目名称/作者标题区 + 多个分区
- UI 组件：分区用 HomeSection，数据行用 ProtoFieldRow（标签：值），控制用 Button

**论文中描述**：可写为"上位机界面采用现代化的声明式 UI 开发方式，将界面划分为若干功能分区，数据显示采用文本形式，控制操作统一使用按钮实现"。
