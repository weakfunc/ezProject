# 白噪音疗愈音箱 — 软件需求文档

---

## 一、项目概述

本项目是一款基于 STM32F103C8T6 的白噪音疗愈音箱，通过本地触控面板（TJC 串口屏）和手机 APP（BLE）双重控制方式，实现白噪音播放、定时关闭、夜灯调光、场景模式切换等功能。

**核心功能：**

1. **音频播放控制**：内置 15 种白噪音（雨声、森林、海浪、溪流、白噪、咖啡馆等），支持上/下一曲、播放/暂停、音量调节（0-100%）、自定义混音（如"雨声+鸟鸣"组合）
2. **多模式定时关闭**：5/10/15/30/60 分钟可选，适配助眠、专注场景
3. **夜灯控制**：亮度 0-100% 可调，暖光 2700K，搭配白噪音增强助眠效果
4. **场景化预设模式**：助眠、专注、冥想、儿童哄睡四种模式，一键切换对应白噪音与亮度组合
5. **双重控制**：本地 TJC 串口屏触控 + 手机 APP 远程（通过 ESP32 BLE 桥接）
6. **串口屏状态显示**：实时显示当前曲目、模式、定时状态、灯光状态、音量

#define TIMER_15MIN         15

#define TIMER_60MIN         60

    MODE_SLEEP = 0,     // 助眠模式

### 3.4 Updata 循环设计

基础周期 2ms，通过 `taskCnt` 取余实现子周期：

| 子周期 | taskCnt 取余 | 功能 |
|--------|-------------|------|
| 2ms | 每次 | taskCnt++，需要周期更新的 driver 的 Update() |
| 10ms | %5==0 | 串口屏命令接收解析（读取串口屏按键帧） |
| 50ms | %25==0 | APP 通信变量读取（从 remoteVar_RX 读取 APP 指令） |
| 100ms | %50==0 | 串口屏状态回显（根据脏标志发送 TJC 指令更新显示）；APP 状态上报（写 remoteVar_TX） |
| 1s | %500==0 | 定时器倒计时递减逻辑 |

**主循环伪代码：**

```c
void user1TaskUpdata(void *argument) {
    user1TaskInit();
    for(;;) {
        user1TaskInfo.taskCnt++;

        // [每2ms] 周期更新 driver
        DRIVER_XXX_Update();  // 根据实际 driver 填写

        // [每10ms] 串口屏按键帧解析
        if(user1TaskInfo.taskCnt % 5 == 0) {
            handleScreenInput();   // 解析串口屏 16 字节帧
        }

        // [每50ms] 读取 APP 遥控指令
        if(user1TaskInfo.taskCnt % 25 == 0) {
            handleAppInput();      // 从 remoteVar_RX 读取并执行
        }

        // [每100ms] 串口屏状态回显 + APP 状态上报
        if(user1TaskInfo.taskCnt % 50 == 0) {
            updateScreenDisplay(); // 根据脏标志发送 TJC 指令
            updateAppTxVars();     // 写 remoteVar_TX
        }

        // [每1s] 定时器倒计时
        if(user1TaskInfo.taskCnt % 500 == 0) {
            handleTimerCountdown();
        }

        osDelay(2);
    }
}
```

| [2] | 1B | 当前音量（0~100） | var_uint32 低8位 |

| [5] | 4B | 保留 | — |
| [6] | 1B | 灯光亮度（0~100） | var_uint32 低8位 |
| [7] | 1B | 当前场景模式（0~3） | var_uint32 低8位 |

### RX（APP → STM32）

| 索引 | 有效宽度 | 变量含义 | 数据类型 |
|------|---------|---------|---------|
| [0] | 4B | APP 指令码（见下方指令码定义） | var_uint32 |
| [1] | 4B | 指令参数（曲目号/音量值/定时分钟数等） | var_uint32 |

| [3] | 1B | 保留 | — |
| [4] | 4B | 保留 | — |
| [5] | 4B | 保留 | — |
| [6] | 1B | 保留 | — |
| [7] | 1B | 保留 | — |

**APP 指令码定义（RX[0]）：**

| 指令码 | 含义 | RX[1] 参数说明 |
|--------|------|---------------|
| 0 | 无指令/空闲 | — |
| 1 | 播放/暂停切换 | — |
| 2 | 上一曲 | — |
| 3 | 下一曲 | — |
| 4 | 设置音量 | 音量值（0~100） |
| 5 | 设置定时 | 分钟数（0/5/10/15/30/60，0=取消） |
| 6 | 设置灯光亮度 | 亮度值（0~100） |

**去重机制：** STM32 端记录上一次处理的指令序号 `lastAppCmdSeq`，每次读取 RX[2]，若与 `lastAppCmdSeq` 不同则执行指令并更新序号，相同则忽略。

## 五、功能详细需求

### 5.1 音频播放控制

**功能描述：** 控制 MP3 模块播放 SD 卡中的 15 首白噪音曲目。

**实现逻辑：**

- **播放/暂停**：收到播放指令时，若当前为停止/暂停状态则发送播放命令给 MP3 driver，切换 `playState` 为 `PLAY_STATE_PLAYING`；若当前为播放状态则发送暂停命令，切换为 `PLAY_STATE_PAUSED`
- **上一曲**：`currentTrack--`，若 <1 则回绕到 15，发送指定曲目播放命令，自动进入播放状态
- **下一曲**：`currentTrack++`，若 >15 则回绕到 1，发送指定曲目播放命令，自动进入播放状态
- **音量调节**：音量+时 `volume += VOLUME_STEP`（上限 100），音量-时 `volume -= VOLUME_STEP`（下限 0），发送音量设置命令给 MP3 driver
- **指定曲目播放**（APP 专用）：直接设置 `currentTrack` 并播放

**涉及的 driver API：** 根据前置步骤发现的 MP3 driver 的 API（预计包含播放、暂停、上/下一曲、设置音量、指定曲目等函数）。

**关键参数：**
- 曲目范围：1~15
- 音量范围：0~100，步长 5
- 默认音量：50

### 5.2 串口屏交互（TJC 串口屏）

**功能描述：** 接收串口屏按键命令，发送状态回显到串口屏。

#### 5.2.1 接收方向：串口屏 → STM32（固定 16 字节帧）

**帧结构：** `[0]0x55 包头1 → [1]0xAA 包头2 → [2]控制字段 → [3]~[12]数据内容(ASCII, 不足补0x00) → [13]0x00 CRC占位 → [14]0x00 CNT占位 → [15]0xFF 包尾`

**控制字段分配：** 0x05=音频控制，0x06=定时控制，0x07=灯光控制，0x08=模式控制

**按钮命令解析表：**

| 按钮 | 控制字段 | 数据内容(ASCII) | 动作 |
|------|---------|---------------|------|
| b0 上一曲 | 0x05 | "PREV" | 上一曲 |
| b1 播放/暂停 | 0x05 | "PLAY" | 播放/暂停切换 |
| b2 下一曲 | 0x05 | "NEXT" | 下一曲 |
| b6 音量+ | 0x05 | "VOL+" | 音量增加 |
| b7 音量- | 0x05 | "VOL-" | 音量减少 |
| b3 定时 | 0x06 | "TIME" | 循环切换定时：关→5→10→15→30→60→关 |
| b4 灯光 | 0x07 | "LIGHT" | 循环切换灯光亮度：关(0)→25→50→75→100→关(0) |
| b5 模式 | 0x08 | "MODE" | 循环切换场景模式：助眠→专注→冥想→哄睡→助眠 |

**解析逻辑：**
1. 从串口屏 driver 获取接收到的帧数据
2. 校验包头 `0x55 0xAA` 和包尾 `0xFF`
3. 根据 `[2]` 控制字段判断功能类别
4. 根据 `[3]~[12]` 数据内容（ASCII 字符串比对）确定具体按钮
5. 执行对应操作，置相关脏标志

#### 5.2.2 发送方向：STM32 → 串口屏（TJC 指令协议）

**格式：** `控件名.txt="内容"` + `0xFF 0xFF 0xFF`，编码 GB2312

**控件映射表：**

| 控件名 | 含义 | 更新内容示例 |
|--------|------|-----------|
| t3 | 当前曲目名 | `t3.txt="雨声"` |
| t4 | 定时状态 | `t4.txt="30m"` 或 `t4.txt="关"` |
| t5 | 灯光状态 | `t5.txt="暖白"` 或 `t5.txt="50%"` |
| t7 | 模式状态 | `t7.txt="助眠"` |
| t10 | 当前音量 | `t10.txt="80"` |

**曲目名称映射表（曲目索引 → 中文名）：**

| 索引 | 名称 | 索引 | 名称 | 索引 | 名称 |
|------|------|------|------|------|------|
| 1 | 雨声 | 6 | 白噪 | 11 | 雨声+鸟鸣 |
| 2 | 森林 | 7 | 咖啡馆 | 12 | 森林+溪流 |
| 3 | 海浪 | 8 | 雷雨 | 13 | 海浪+风声 |
| 4 | 溪流 | 9 | 风声 | 14 | 篝火 |
| 5 | 鸟鸣 | 10 | 虫鸣 | 15 | 城市夜景 |

> **注意：** 曲目名称表以 `const char*` 数组形式定义在 `task_user1.c` 中，使用 GB2312 编码（Keil 项目默认编码），发送时直接引用。

**脏标志刷新逻辑：** 每 100ms 检查各脏标志，仅在标志为 1 时发送对应 TJC 指令，发送后清 0。避免频繁刷屏。

### 5.3 定时关闭功能

**功能描述：** 设定倒计时，到时自动停止播放并关闭灯光。

**实现逻辑：**

- **定时设置**：串口屏 b3 按钮循环切换 `timerSetting`：`0→5→10→15→30→60→0`（分钟）
  - 设为 0 时：`timerState = TIMER_STATE_IDLE`，`timerRemainSec = 0`
  - 设为非 0 时：`timerState = TIMER_STATE_RUNNING`，`timerRemainSec = timerSetting * 60`
- **倒计时**：每 1s（taskCnt % 500 == 0），若 `timerState == TIMER_STATE_RUNNING`：
  - `timerRemainSec--`
  - 若 `timerRemainSec == 0`：执行定时到期动作
- **定时到期动作**：
  1. 发送暂停命令给 MP3 模块，`playState = PLAY_STATE_PAUSED`
  2. 关闭灯光 `lightBrightness = 0`，发送 PWM=0 命令
  3. `timerState = TIMER_STATE_IDLE`，`timerSetting = 0`
  4. 置所有相关脏标志

**串口屏定时显示：**
- `timerSetting == 0` 时显示 `"关"`
- 运行中显示剩余分钟数（`timerRemainSec / 60`），如 `"29m"`

### 5.4 夜灯控制

**功能描述：** 控制 PWM 输出驱动暖光 LED，亮度 0-100% 可调。

**实现逻辑：**

- **串口屏 b4 按钮**：循环切换亮度档位 `0→25→50→75→100→0`
- **APP 控制**：直接设置任意亮度值（0~100）
- **亮度值 → PWM 占空比**：`pwmDuty = lightBrightness * MAX_PWM / 100`（MAX_PWM 根据 driver 实际 PWM 周期确定）
- **状态显示**：串口屏 t5 控件显示当前亮度百分比，如 `"50%"`，亮度为 0 时显示 `"关"`

**涉及的 driver API：** PWM 输出 driver 的设置占空比函数。

### 5.5 场景化预设模式

**功能描述：** 四种预设模式，一键切换白噪音曲目与灯光亮度组合。

**预设参数表：**

| 模式 | 枚举值 | 默认曲目 | 默认灯光亮度 | 中文名 |
|------|--------|---------|------------|--------|
| 助眠 | MODE_SLEEP | 1（雨声） | 25% | "助眠" |
| 专注 | MODE_FOCUS | 6（白噪） | 0%（关灯） | "专注" |
| 冥想 | MODE_MEDITATE | 4（溪流） | 50% | "冥想" |
| 儿童哄睡 | MODE_BABY | 5（鸟鸣） | 15% | "哄睡" |

**实现逻辑：**

- **切换模式**：串口屏 b5 按钮循环切换 `currentMode`：`0→1→2→3→0`
- **切换时执行**：
  1. 根据预设参数表设置 `currentTrack` 和 `lightBrightness`
  2. 发送指定曲目播放命令，进入播放状态
  3. 发送灯光亮度 PWM 命令
  4. 置所有相关脏标志
- **模式切换不影响定时**：切换模式时保持当前定时设置不变
- **模式切换后手动调节**：切换模式后用户仍可手动调节曲目/音量/灯光，不会自动回弹

### 5.6 APP 远程控制

**功能描述：** 通过 BLE（ESP32 桥接）接收 APP 指令并执行。

**实现逻辑：**

- 每 50ms 读取 `remoteInfo.remoteVar_RX[]`
- 检查 `RX[2]`（指令序号）是否与 `lastAppCmdSeq` 不同
- 若不同，根据 `RX[0]`（指令码）和 `RX[1]`（参数）执行对应操作（复用与串口屏相同的处理函数）
- 更新 `lastAppCmdSeq`
- 每 100ms 将当前状态写入 `remoteVar_TX[]`，APP 端轮询读取

**APP 可执行的操作与串口屏一致**，额外支持：
- 精确设置音量值（而非步进）
- 指定曲目播放
- 精确设置灯光亮度值（而非档位切换）

## 六、driver 层修改需求

**需根据前置步骤的 driver 扫描结果确定。以下为预判可能需要的修改，Claude Code 在实际扫描 driver 后确认：**

1. **串口屏 driver（如 `drv_tjc` 或 `drv_screen`）**：
   - 如果现有 driver 仅提供原始 UART 收发，可能需要新增帧解析辅助函数
   - 如果现有 driver 已提供 16 字节帧接收和 TJC 指令发送功能，则无需修改

2. **MP3 driver（如 `drv_mp3` 或 `drv_audio`）**：
   - 确认是否提供：播放、暂停、上/下一曲、指定曲目、设置音量等完整 API
   - 如缺少某些功能（如指定曲目播放），需要扩展

3. **PWM/灯光 driver（如 `drv_pwm` 或 `drv_led`）**：
   - 确认是否提供占空比设置 API
   - 如现有 API 不支持平滑调光，可考虑在 task 层做渐变逻辑

> **修改原则：** 修改 driver 层时必须遵守 driver 层接口规范和命名规范（`DRIVER_XXX_Init()` / `DRIVER_XXX_Update()` / `DRIVER_XXX_DoSomething()` / `xxxInfo` 结构体），并在 `implementation_report.md` 中明确记录修改内容。

#### (c) 已实现功能的测试步骤

**测试 1：音频播放控制**
- 测试方法：上电后按串口屏 b1（播放），观察 MP3 模块是否输出声音；按 b0/b2 切换曲目，观察串口屏 t3 是否更新曲目名；按 b6/b7 调节音量，观察串口屏 t10 是否更新音量值
- 预期结果：播放/暂停正常切换，曲目循环切换（15→1，1→15），音量 0~100 范围内步进调节

**测试 2：串口屏交互**
- 测试方法：依次按下所有按钮（b0~b7），观察串口屏各控件（t3/t4/t5/t7/t10）是否正确刷新
- 预期结果：每次按键后对应控件 100ms 内更新显示

**测试 3：定时关闭**
- 测试方法：播放音乐并开灯，按 b3 设置 5 分钟定时，观察串口屏 t4 显示倒计时分钟数，等待 5 分钟
- 预期结果：5 分钟后自动停止播放、关闭灯光，t4 显示 "关"

**测试 4：夜灯控制**
- 测试方法：按 b4 循环切换灯光，观察 LED 亮度变化和串口屏 t5 显示
- 预期结果：亮度按 关→25%→50%→75%→100%→关 循环，LED 亮度可见变化

**测试 5：场景模式**
- 测试方法：按 b5 切换模式，观察曲目和灯光是否自动切换到预设值
- 预期结果：助眠=雨声+25%灯光，专注=白噪+灯关，冥想=溪流+50%灯光，哄睡=鸟鸣+15%灯光

**测试 6：APP 远程控制**
- 测试方法：通过 APP 发送各种指令（播放、切曲、调音量、设定时、调灯光、切模式），观察 STM32 是否响应
- 预期结果：与串口屏操作效果一致，APP 端能实时读到更新后的状态

## 编码约束（codex 必须遵守）

| 约束项 | 规则 |
|--------|------|
| 内存分配 | 禁止 malloc，全部静态分配 |
| 注释语言 | 中文 |
| 私有定义 | 写在 .c 文件中 |
| 公有定义 | 写在 .h 文件中 |
| 命名风格 | task层：小驼峰（user1TaskInit）；结构体：xxxTaskInfo_t；宏：MODULE_CONSTANT |
| 额外功能 | 不实现需求未提及的功能 |
| task层调用 | 可调用 stdlib层、driver层、func层，禁止直接调用 HAL |
| 不可修改 | task_system.c/.h、stdlib 层（userLib/）、HAL 层（Core/） |
| driver 修改 | 仅在现有 API 不足时允许，必须遵守 driver 接口规范和命名规范，标注修改点 |
| 串口屏编码 | TJC 指令字符串必须使用 GB2312 编码 |
