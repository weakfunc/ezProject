## 1. 项目软硬件平台

- 主控芯片：STM32F103C8T6（Cortex-M3，72MHz，64KB Flash，20KB SRAM）
- 软件库：STM32 HAL 库
- 操作系统：FreeRTOS（CMSIS_V2 接口）
- 开发环境：MDK-ARM Keil 5

## 2. 软件分层结构（论文中需用通用术语改写）

项目软件按职责划分为五层（自上而下）：

| 内部叫法 | 论文中表述（建议） | 职责 |
|---|---|---|
| task 层（userApp） | 应用层 / 任务层 | 业务逻辑，开发者主要工作区 |
| func 层（userFunc） | 功能模块层 / 中间件层 | 跨驱动的逻辑整合，如通信处理 |
| driver 层（userDriver） | 驱动层 | 各外设的驱动封装 |
| stdlib 层（userLib） | 基础库 / 工具库 | 通用工具函数（延时、CRC、字符串等） |
| HAL 层（Core/） | 硬件抽象层 | ST 官方 HAL 库 |

调用规则：上层可调用下层，禁止跨层（应用层不直接调 HAL）。

## 3. FreeRTOS 任务规划

项目固定使用两个 FreeRTOS 任务：

| 任务名 | 周期 | 职责 |
|---|---|---|
| task_system | 10ms | 系统级周期任务，维护基础库状态机和通信更新 |
| task_user1 | 2ms | 应用级任务，承担主要业务逻辑 |

task_user1 内部通过 `taskCnt` 计数器取余实现多周期：

```c
if (taskCnt % 5 == 0)   { /* 10ms 周期逻辑 */ }
if (taskCnt % 50 == 0)  { /* 100ms 周期逻辑 */ }
if (taskCnt % 250 == 0) { /* 500ms 周期逻辑 */ }
if (taskCnt % 500 == 0) { /* 1s 周期逻辑 */ }
```

**论文中描述**：可写为"主任务以 2ms 为基础调度周期，通过计数器取余实现 10ms / 100ms / 500ms / 1s 等多级时间片"。

## 4. 命名规范（论文中提到代码命名时遵守）

- 任务函数：`xxxTaskInit()` / `xxxTaskUpdata()`（注意是 Updata 不是 Update，这是项目代码实际拼写）
- 任务结构体：`xxxTaskInfo_t` + `extern xxxTaskInfo_t xxxTaskInfo`
- 驱动函数：`DRIVER_XXX_Init()` / `DRIVER_XXX_Update()` / `DRIVER_XXX_DoSomething()`
- 驱动结构体：`xxxInfo` 或 `xxxInfo[CH_COUNT]`
- 命名风格：小驼峰（变量/函数）+ 大驼峰_t（结构体）+ 全大写_下划线（宏）
- 注释语言：中文
- 内存分配：全静态分配，禁用 malloc

## 5. 通信链路（若项目有 BLE/APP 通信）

通信链路结构：

```
STM32 ←USART1→ ESP32 ←BLE→ 手机 APP
```

- STM32 通过 USART1 与 ESP32 通信，统一使用 16 字节定长帧
- ESP32 作为 BLE 协处理器，将 STM32 数据透传给 APP，反之亦然
- 应用层通过 `remoteVar_TX[16]` / `remoteVar_RX[16]` 两个变量池读写，不需要操作底层帧

`remoteVar_t` 是 4 字节联合体：

```c
typedef union {
    uint8_t  raw[4];
    uint32_t var_uint32;
    int32_t  var_int32;
    float    var_float;
} remoteVar_t;
```

槽位有效宽度：

- TX/RX 索引 [0][1][4][5][8][9][12][13] → 4 字节槽位（float / uint32 / int32）
- TX/RX 索引 [2][3][6][7][10][11][14][15] → 1 字节槽位

**关键约束**：TX[0]~[3] 不会到达 APP（被 ESP32 截留），发送给 APP 的数据使用 TX[4]~[15]。

**论文中描述**：可写为"主控通过串口与无线通信模块交换数据，无线通信模块再通过低功耗蓝牙将数据透传至手机端。为简化业务层代码，作者设计了变量池机制，应用层只需读写约定的变量数组即可完成双向通信"。

## 6. 字节序处理（论文若涉及通信细节）

APP 端以大端序发送 4 字节字段，STM32 端 USART 接收处理函数已自动翻转为小端序。**应用层直接读写 remoteVar 即可，无需关心字节序**。

## 7. 上位机（若项目有 APP）

- 平台：Android 原生
- UI 框架：Jetpack Compose + Material Design 3
- 通信：BLE GATT
- 主页面：单页 HomeScreen，包含项目名称/作者标题区 + 多个分区
- UI 组件：分区用 HomeSection，数据行用 ProtoFieldRow（标签：值），控制用 Button

**论文中描述**：可写为"上位机界面采用现代化的声明式 UI 框架开发，将界面划分为若干功能分区，数据显示采用文本形式，控制操作统一使用按钮实现，避免滑动控件可能带来的误触和精度问题"。

## 8. 论文写作指引

撰写第四章软件设计时，Claude 应当：

1. **从作者视角讲述设计思路**，不要写成"项目使用了 XX 框架"——而是"作者经过分析后采用了 XX 设计方案"
2. **代码命名直接使用项目实际命名**（user1TaskInfo、DRIVER_XXX_Init 等），但解释命名时说"作者按照模块化原则采用统一的命名风格"
3. **分层结构用通用工程术语描述**，不要出现 task/driver/stdlib 这种内部叫法
4. **2ms 基础周期 + taskCnt 取余**这套机制要解释为"作者的设计巧思"，而不是"框架要求"
5. **遇到代码细节时**，结合代码本身解释作者的实现思路，让论文显得是真的写过这份代码
6. **每段贴出的代码都要有对应小节解释**，不能贴而不讲
